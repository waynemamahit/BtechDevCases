## 1. user-registration

- [x] 1.1 Create `api/db/schema.sql` with table `users` (`id` CHAR(36) primary key, `email` VARCHAR(255) `utf8mb4_bin` NOT NULL, `password_hash` VARCHAR(255) NOT NULL) and unique key `users_email_unique` on `email`. Create `api/db/query.sql` with sqlc queries `CreateUser` and `GetUserByEmail`. Create `api/sqlc.yaml` (MySQL engine, schema `db/schema.sql`, queries `db/query.sql`, Go package `db` written to `internal/db`). Generate and commit `api/internal/db`. Verify `sqlc generate` from `api/` reproduces that package from those two SQL files.
- [x] 1.2 Create registration checks in `api/internal/user/register.go` and cover them in `api/internal/user/register_test.go`: missing `email`, missing `password`, missing `confirmPassword`, `email` `not-an-email`, empty `password`, and `confirmPassword` that differs from `password`. No trimming and no case folding. These tests do not open MySQL. Verify `go test ./internal/user` from `api/` passes.
- [x] 1.3 Create `api/internal/user/store.go`: validate, bcrypt-hash the password, insert only through sqlc `CreateUser`, and map MySQL error 1062 from `users_email_unique` to the duplicate-email error. `Authenticate` loads the row only through sqlc `GetUserByEmail`. Create `POST /register` in `api/internal/httpapi/server.go` with `api/internal/httpapi/register_test.go`. Accepted input returns `201` and JSON `{ "id", "email" }` only, with no token and no password. Each validation failure returns `400` and creates no account. Those HTTP tests use a test directory, not MySQL. Verify `go test ./internal/httpapi` from `api/` passes the registration cases.
- [x] 1.4 Create `api/internal/user/duplicate_mysql_test.go`. It starts MySQL 8, applies `api/db/schema.sql`, and registers through the sqlc store. A second registration of the same email fails because `users_email_unique` rejects the insert, the stored secret is a bcrypt hash of the first password and not the submitted password, and a different-case email is stored as a separate account. Verify that test passes.

## 2. jwt-session

- [x] 2.1 Create `api/internal/token/token.go` with a `Clock` interface (`Now() time.Time`), HMAC signing via `JWT_SECRET` (`github.com/golang-jwt/jwt/v5`), and claims `sub`, `email`, `iat`, and `exp`. Sign truncates the clock to a UTC second, then sets `iat` to that instant and `exp` to 15 minutes later. A token is valid only while `now < exp`. Verify `go test ./internal/token` from `api/` passes `api/internal/token/token_test.go`, using a fake clock, for those claims and for rejection at exactly 15 minutes.
- [x] 2.2 Create `POST /login` on the server in `api/internal/httpapi/server.go` and `api/internal/httpapi/login_test.go`. The registered email and password return `200` and `{ "token" }` whose `sub` and `email` match the stored user. A second login returns the same `sub`. An unknown email and a wrong password each return `401`, `{ "error": "invalid credentials" }`, and no token. Verify `go test ./internal/httpapi` from `api/` passes.
- [x] 2.3 Create `GET /me` on the same server and `api/internal/httpapi/session_test.go`, both using the fake clock. `Authorization: Bearer` with a valid token returns `200` and `{ "id", "email", "token" }` where `token` is a new credential. A missing token and a token this server did not sign return `401` and no new token. A request 14 minutes after issue succeeds and returns a credential that `GET /me` still accepts 14 minutes later and rejects 15 minutes after that renewal. The unrenewed credential is rejected 15 minutes after it was issued. Verify `go test ./internal/httpapi` from `api/` passes.
- [x] 2.4 Create `api/cmd/api/main.go` and `api/internal/httpapi/config.go`. The process exits when `JWT_SECRET`, `WEB_ORIGIN`, or `DATABASE_DSN` is empty, opens MySQL with `DATABASE_DSN`, pings before listening, listens on `API_PORT` (default `8080`), and allows CORS from `WEB_ORIGIN` for `GET`, `POST`, and `OPTIONS` with `Content-Type` and `Authorization`. The server constructed here uses the sqlc store. Verify `go test ./...` from `api/` passes, including a config test that an empty `JWT_SECRET`, `WEB_ORIGIN`, or `DATABASE_DSN` is rejected.
