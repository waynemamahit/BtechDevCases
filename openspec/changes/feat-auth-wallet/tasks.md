# Tasks

## 1. user-registration

- [x] 1.1 Create `api/db/schema.sql` with the finished tables from `design.md`: `users` (`id`, case-sensitive unique `email`, `password_hash`, nullable `last_activity_at`), `wallets` (`user_id`, `balance_minor`), and `transfers` (primary key `(sender_id, id)`, `recipient_id`, `amount_minor`, `notes` of at most 200 characters, `created_at`). Verify the file defines those three tables, the email unique key, and `utf8mb4_bin` on `email`.
- [x] 1.2 Create `api/db/query.sql` and `api/sqlc.yaml`, generate `api/internal/db`, and commit that package. The queries create a user, create a wallet, load a user by email, read and set `last_activity_at`, lock a wallet, set a balance, insert a transfer, load a transfer by sender and id, and list the transfers a user sent or received. Verify `go build ./internal/db/` from `api/` succeeds.
- [x] 1.3 Create `api/internal/user/register.go` and `api/internal/user/register_test.go` so a missing `email`, `password`, or `confirmPassword` is rejected as `email is required`, `password is required`, or `confirmPassword is required`, an invalid or empty email is rejected as `email is not a valid address`, an empty password is rejected as `password must be non-empty` before the confirmation is compared, and a different confirmation is rejected as `confirmPassword does not match password`. Verify `go test ./internal/user/ -run TestValidate -count=1` from `api/` passes.
- [x] 1.4 Create `api/internal/user/store.go` and `api/internal/user/duplicate_mysql_test.go` so registration stores a bcrypt hash, inserts the user and a wallet of `100000` in one transaction, a second registration of the same email fails on the MySQL unique key, and `Ada@example.com` is a different account from `ada@example.com`. Verify `go test ./internal/user/ -run TestDuplicateEmail -count=1` from `api/` passes against MySQL 8 loaded with `api/db/schema.sql`.
- [x] 1.5 Create `api/internal/httpapi/config.go`, `api/internal/httpapi/config_test.go`, `POST /register` in `api/internal/httpapi/server.go`, and `api/internal/httpapi/register_test.go`. Config requires `JWT_SECRET` and `DATABASE_DSN`, and defaults `API_PORT` to `8080`. It does not read a browser origin. The route returns `201` with `id` and `email` and without the password, `400` JSON `{ "error" }` for each validation failure using the messages from task 1.3, and `409` with error `email is already registered`. Verify `go test ./internal/httpapi/ -run "TestLoadConfig|TestRegister" -count=1` from `api/` passes.
- [x] 1.6 Create `api/Dockerfile`, `compose.yaml`, and `.env.example` for the finished stack. Compose runs MySQL 8 with the named volume `mysql-data`, a healthcheck, and `api/db/schema.sql` applied on first init, and the API starts only after MySQL is healthy. Compose does not run a Flutter service. The API service receives `JWT_SECRET`, `DATABASE_DSN`, and `API_PORT`. Verify `compose.yaml` has a `mysql` service and an `api` service and no Flutter service, and `.env.example` lists `JWT_SECRET`, `DATABASE_DSN`, `API_PORT`, `MYSQL_ROOT_PASSWORD`, `MYSQL_DATABASE`, `MYSQL_USER`, and `MYSQL_PASSWORD`.

## 2. jwt-session

- [x] 2.1 Create `api/internal/token/token.go` and `api/internal/token/token_test.go` so the issuer signs an HS256 JWT whose `sub` is the user id, whose `email` is the account email, and whose `exp` is 24 hours after `iat`, using an injectable clock. Parse accepts that token and rejects a bad signature or an expired token. Verify `go test ./internal/token/ -count=1` from `api/` passes.
- [x] 2.2 Create authentication and the login activity write in `api/internal/user/store.go`, `POST /login` in `api/internal/httpapi/server.go`, and `api/internal/httpapi/login_test.go`. Matching credentials return `200` and a token whose `sub` and `email` match the account, and set `last_activity_at`. A wrong password returns `401` with error `invalid credentials` and no token. Verify `go test ./internal/httpapi/ -run TestLogin -count=1` from `api/` passes.
- [x] 2.3 Create the idle check and `GET /me` in `api/internal/httpapi/server.go`, plus `api/internal/httpapi/session_test.go`, using one manual clock for the token and the idle check. `GET /me` with a live session returns `200` and the body is exactly `Hello ada@example.com, welcome back` with no extra characters. A missing token returns `401`. A call 14 minutes after login, and another call 14 minutes after that success, each return the welcome sentence. A call 15 minutes after the last success returns `401` and does not move the clock, so a call one minute later is still `401`. A request whose context is already canceled returns `504` and does not move the clock. Verify `go test ./internal/httpapi/ -run TestSession -count=1` from `api/` passes.
- [x] 2.4 Create the Flutter app under `app/` with `app/lib/config.dart`, `app/lib/session.dart`, `app/lib/welcome.dart`, `app/lib/api_client.dart`, `app/lib/error_alert.dart`, and `app/lib/main.dart`. The app reads `API_BASE_URL` from `--dart-define` and defaults to `http://10.0.2.2:8080`. Register and login screens post the spec fields. A `400`, `401`, or `409` whose JSON body has a non-empty `error` string is shown in the error alert. A timeout, a status of 500 or higher, or a dropped connection shows `Request failed`. The signed-in screen shows the welcome sentence from the stored email. The session stores the last successful login or authenticated request, and on resume clears itself at 15 minutes without calling the API. A failed call does not move that time. Android allows cleartext HTTP. Verify `flutter test test/welcome_test.dart test/session_test.dart` from `app/` passes.

## 3. wallet

- [x] 3.1 Create `api/internal/wallet/wallet.go` so a read returns the caller's balance and their sent and received transfers, and a transfer locks both wallets in one transaction, debits and credits once, replays the same sender transfer id without moving money, and rejects a different payload, an unknown recipient, a self-transfer, and an amount above the locked balance. Verify the package builds with `go build ./internal/wallet/` from `api/`.
- [x] 3.2 Create `GET /wallet` and `POST /transfers` in `api/internal/httpapi/server.go` and `api/internal/httpapi/wallet_test.go`. Cover an opening read of `100000` and no transfers, a transfer that leaves the sender at `97500` and the recipient at `102500`, empty notes, notes of 201 characters as `400` `notes must be at most 200 characters`, a zero or negative amount as `400` `amount must be a positive integer`, an unknown recipient as `404` `recipient not found`, a self-transfer as `400` `cannot transfer to self`, insufficient funds as `409` `insufficient funds`, the same transfer id with the same payload, and the same id with a different amount as `409` `transfer id reused with a different payload`. Also cover a wallet read that keeps `GET /me` valid 14 minutes later, and a failed transfer that leaves a protected call 15 minutes after login rejected. Verify `go test ./internal/httpapi/ -run TestWallet -count=1` from `api/` passes.
- [x] 3.3 Create `api/internal/wallet/transfer_mysql_test.go` against MySQL 8 loaded with `api/db/schema.sql`. Prove a new account's stored balance is `100000`, a transfer changes both stored balances once, and repeating that transfer id does not change them again. Verify `go test ./internal/wallet/ -run TestTransferMySQL -count=1` from `api/` passes.
- [x] 3.4 Create `api/cmd/api/main.go` so the process loads config, pings MySQL with a 5-second timeout, and serves registration, login, `GET /me`, `GET /wallet`, and `POST /transfers` with the design deadlines: 5-second read-header timeout, 10-second read and write timeouts, 60-second connection idle timeout, and an 8-second request deadline. Verify `go build -o api.exe ./cmd/api` from `api/` succeeds and `go test ./...` from `api/` passes.
- [x] 3.5 Create `app/lib/money.dart`, `app/lib/transfer_draft.dart`, `app/lib/transfer_history.dart`, `app/test/wallet_client_test.dart`, `app/test/wallet_screen_test.dart`, and the signed-in wallet form in `app/lib/main.dart`. The screen shows a balance of 100000 minor units as `1000.00`. After a successful wallet read, History shows one row per transfer with `Received` or `Sent`, the two-decimal amount, the counterparty, and the notes when they are not empty. An empty list shows `No transfers yet`. The form submits recipient, amount, and notes. An empty recipient, a non-positive amount, an amount with more than two decimal places, and notes longer than 200 characters are all shown together in the error alert, and that submit does not send the request. A `400`, `404`, or `409` whose JSON `error` is non-empty shows that text. A timeout, a status of 500 or higher, or a dropped connection shows `Request failed`, leaves the displayed balance at the last successful read, and does not move the activity time. Retry sends the same transfer id. Editing the amount replaces the id. The HTTP client times out after 12 seconds. Verify `flutter test test/wallet_client_test.dart test/wallet_screen_test.dart` from `app/` passes.

Verify those names appear in `readme.md`.
