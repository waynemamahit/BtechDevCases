## 1. user-registration

- [x] 1.1 Create `api/db/schema.sql` with the finished tables from `design.md`: `users` (`id`, case-sensitive unique `email`, `password_hash`, nullable `last_activity_at`), `wallets` (`user_id`, `balance_minor`), and `transfers` (primary key `(sender_id, id)`, `recipient_id`, `amount_minor`, `notes` of at most 200 characters, `created_at`). Verify the file defines those three tables, the email unique key, and `utf8mb4_bin` on `email`.
- [x] 1.2 Create `api/db/query.sql` and `api/sqlc.yaml`, generate `api/internal/db`, and commit that package. Verify `go build ./internal/db/` from `api/` succeeds.
- [x] 1.3 Create `api/internal/user/register.go` and `api/internal/user/register_test.go` so a missing `email`, `password`, or `confirmPassword` is rejected, an invalid or empty email is rejected, an empty password is rejected before the confirmation is compared, and a different confirmation is rejected. Verify `go test ./internal/user/ -run TestValidate -count=1` from `api/` passes.
- [x] 1.4 Create `api/internal/user/store.go` and `api/internal/user/duplicate_mysql_test.go` so registration stores a bcrypt hash, inserts the user and a wallet of `100000` in one transaction, a second registration of the same email fails on the MySQL unique key, and `Ada@example.com` is a different account from `ada@example.com`. Verify `go test ./internal/user/ -run TestDuplicateEmail -count=1` from `api/` passes against MySQL 8 loaded with `api/db/schema.sql`.
- [x] 1.5 Create `api/internal/httpapi/config.go`, `api/internal/httpapi/config_test.go`, `POST /register` in `api/internal/httpapi/server.go`, and `api/internal/httpapi/register_test.go`. Config requires `JWT_SECRET`, `DATABASE_DSN`, and `WEB_ORIGIN`, and defaults `API_PORT` to `8080`. The route returns `201` with `id` and `email` and without the password, `400` for each validation failure, and `409` for a duplicate email, and it allows the configured browser origin. Verify `go test ./internal/httpapi/ -run "TestLoadConfig|TestRegister" -count=1` from `api/` passes.
- [x] 1.6 Create `api/Dockerfile`, `compose.yaml`, `.env.example`, and `readme.md` for the finished stack. Compose runs MySQL 8 with the named volume `mysql-data`, a healthcheck, and `api/db/schema.sql` applied on first init, and the API starts only after MySQL is healthy. There is no UI service. The README documents `docker compose up --build`, states that minor units are two decimal places, and lists `JWT_SECRET`, `DATABASE_DSN`, `API_PORT`, `WEB_ORIGIN`, `MYSQL_ROOT_PASSWORD`, `MYSQL_DATABASE`, `MYSQL_USER`, and `MYSQL_PASSWORD`. Verify those names appear in `readme.md` and `compose.yaml` has a `mysql` service and an `api` service and no web service.

## 2. jwt-session

- [x] 2.1 Create `api/internal/token/token.go` and `api/internal/token/token_test.go` so the issuer signs an HS256 JWT whose `sub` is the user id, whose `email` is the account email, and whose `exp` is 24 hours after `iat`, using an injectable clock. Parse accepts that token and rejects a bad signature or an expired token. Verify `go test ./internal/token/ -count=1` from `api/` passes.
- [x] 2.2 Create authentication and the login activity write in `api/internal/user/store.go`, `POST /login` in `api/internal/httpapi/server.go`, and `api/internal/httpapi/login_test.go`. Matching credentials return `200` and a token whose `sub` and `email` match the account, and set `last_activity_at`. A wrong password returns `401` and no token. Verify `go test ./internal/httpapi/ -run TestLogin -count=1` from `api/` passes.
- [x] 2.3 Create the idle check and `GET /me` in `api/internal/httpapi/server.go`, plus `api/internal/httpapi/session_test.go`, using one manual clock for the token and the idle check. `GET /me` with a live session returns `200` and the body is exactly `Hello ada@example.com, welcome back` with no extra characters. A missing token returns `401`. A call 14 minutes after login, and another call 14 minutes after that success, each return the welcome sentence. A call 15 minutes after the last success returns `401` and does not move the clock, so a call one minute later is still `401`. A request whose context is already canceled returns `504` and does not move the clock. Verify `go test ./internal/httpapi/ -run TestSession -count=1` from `api/` passes.
